# UO Memento Mobile 0.2.17

Extends **Cold-load timing (Thor test)** to separate the resource/loading/locking work inside long Draw and packet intervals and connect native graphics waits with previous submissions/resources. It retains the existing long-frame, FNA, packet, atlas, allocation/GC/CPU, shader/pipeline and Android presentation measurements. **Mark test phase** identifies the new outdoor/interior/re-entry/retrace session in the exported ZIP.

The option defaults off and this pass uses the recovered **original SDL 3.2.27** baseline. If the optional SDL update preference was left on, the diagnostic launch restores the verified original; a missing backup blocks that known updated-library combination. Keep the optional SDL update OFF on Thor. Turn Cold-load timing off and relaunch after the test to restore the existing client/atlas assemblies. Keep Turnip / Native Surface, 60 FPS and other settings, with Smooth world loading on. The 0.2.13 summaries and 0.2.14 batching are retained. This release does not change synchronization, packet budgets or resource-loading behavior to claim a performance fix.

Install over the working app after logging out and saving/stopping the session. Application ID, signing certificate, installed Wine/FEX runtime, changed-region delivery, Surface geometry caching, audio, server, controls and viewport behavior are retained. **Back to Launcher Menu** remains the quick-menu return label.

See the [Thor test procedure](https://github.com/Russianranger/uo-android-launcher/releases/download/v0.2.17/UO-Memento-Mobile-0.2.17-Instructions.txt) and [diagnostic record guide](https://github.com/Russianranger/uo-android-launcher/blob/main/docs/DIAGNOSTICS-0.2.17.md). Analyze the resulting logs before choosing the next measured optimization.
